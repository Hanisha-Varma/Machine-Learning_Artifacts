Artifact 01

The Daily Brew — AI Customer Assistant

AI CHATBOT
IntroductionAn AI-powered customer service chatbot built for a small cafe, designed and tested end-to-end using the design thinking framework (Empathize, Define, Ideate, Prototype, Test).
DescriptionA conversational assistant that answers customer questions about hours, menu and pricing, dietary accommodations, offers, loyalty program, reservations, and catering — and knows when to hand off to a human staff member instead of guessing.
ObjectiveTo design and build a working AI assistant that solves a real small-business problem: answering repetitive customer questions instantly, without requiring 24/7 staff availability.
ProcessStarted with empathy for the end user (cafe customers wanting fast answers) before writing a line of configuration. Built a structured knowledge base covering the café's operations, then wrote custom behavioral instructions defining tone and strict boundaries (e.g., never promising allergen-free food, never committing to large catering orders). Tested with real conversations, including a simulated complaint, and used the results to identify a concrete improvement (more empathetic complaint handling) for future iteration.

MACHINE LEARNING

AI/ML Data Challenge Scenarios

Production Machine Learning Decision Making — working through real-world data challenges the way an AI Developer would inside a live enterprise system.

This artifact demonstrates how I approached three real-world production machine learning challenges using structured reasoning rather than memorizing algorithms. The exercise reflects how AI Developers and Machine Learning Engineers actually troubleshoot problems in enterprise environments — starting from business context, not just technical metrics.

Objective

To evaluate my ability to think through production ML challenges involving missing data, class imbalance, data drift, and concept drift — using both business context and machine learning best practices rather than applying textbook solutions in isolation.

Scenario Walkthroughs
📊

Handling Missing Data

  • Investigated why values were missing before taking action
  • Identified patterns in the missing data rather than assuming randomness
  • Avoided the shortcut of dropping 20% of records
  • Used indicator features to preserve signal from missingness itself
  • Performed intelligent, context-aware imputations
  • Validated that imputed values still made business sense
Takeaway: Good machine learning starts with understanding why data is missing before trying to fix it.
⚖️

Imbalanced Fraud Detection

  • Scenario: 500,000 transactions, only 0.8% fraudulent
  • Recognized that accuracy alone would be misleading at this ratio
  • Evaluated using Precision, Recall, F1 Score, and PR-AUC
  • Applied SMOTE and class weighting to rebalance learning signal
  • Tuned decision thresholds against real business cost
  • Weighed the cost of false negatives against false positives
Takeaway: Machine learning should optimize business outcomes — not just accuracy.
📈

Data Drift & Concept Drift

  • Diagnosed feature distribution changes over time
  • Identified shifts in the relationship between features and outcomes
  • Flagged calibration issues surfacing in live predictions
  • Traced drift back to external business and market changes
  • Designed monitoring dashboards to catch drift early
  • Defined a retraining and feature engineering strategy
Takeaway: Production AI models require continuous monitoring because data evolves over time.
🏢

Enterprise Perspective

  • Connected prior enterprise analytics experience to ML thinking
  • Applied root cause analysis before proposing a fix
  • Enforced data validation and business rules at every stage
  • Treated monitoring and governance as ongoing responsibilities
  • Framed every technical decision around continuous improvement
Takeaway: Enterprise AI succeeds when technical decisions align with business objectives.
